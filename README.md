# AI Anti-Scam Bot V2

Telegram-бот для обнаружения скама с независимой модерацией нескольких рабочих групп. Одна админская группа может управлять несколькими рабочими: срабатывания приходят в общую ленту, а каждое действие относится только к группе карточки. Роли, вайтлист, блэклист, страйки и настройки изолированы по рабочим группам.

**Статус:** V2 реализована и проверена локально и отдельным тестовым Telegram-ботом. Публикация кода не означает обновление production: боевое переключение и смена модели выполняются отдельно. Результаты проверки кода, 150 автотестов и повторной миграционной репетиции — в [аудите от 14.11.2026](docs/AUDIT_2026-11-14.md); оставшиеся условия выпуска — в [отчёте реализации](docs/IMPLEMENTATION_STATUS.md).

## Возможности

- Подключение из личного чата: администратор подаёт заявку, владелец бота рассматривает её перед активацией. Выбор групп кнопками, резервный выбор и ручной ввод ID; возможны разные подтверждающие. Права проверяются заново перед подключением. Технические команды в рабочей группе не нужны; проверочная карточка отправляется только в админскую.
- Роли владельца, управляющего, модератора и наблюдателя. Актуальные права проверяются при каждом действии; подтверждения персональные, одноразовые и ограничены по времени.
- Автовайтлист по умолчанию после **5 подходящих публикаций именно в этой группе**. Учитываются полностью проверенные `OK` и человеческий `NOT_SCAM`; порог и включение настраиваются. Отзыв доверия начинает новый цикл. Понижение порога не запускает массовую выдачу.
- Простые настройки с кнопками и пояснениями: режим, автовайтлист, число сообщений до доверия, проверка администраторов. Наказания, уведомления и дополнительные параметры вынесены отдельно. **Бюджеты и расходы доступны только владельцу бота в личном чате**, включая общий дневной лимит и лимиты отдельных групп.
- Текст, подписи, изображения с OCR на русском, украинском и английском, ссылки, правки и альбомы. Цитируемый текст отделён от собственной публикации; сбои проверки не считаются безопасным ответом.
- Карточки вероятного скама с уверенностью модели, причиной, текстом, понятной датой и копируемым Telegram ID рядом с именем. Под карточкой — «Не скам», «Бан», «Мут», «Вайтлист», удаление и подробности. Вайтлист и обычные настройки применяются сразу; бан и мут требуют короткого подтверждения. Автовайтлист публикует отдельную карточку в ленте.
- Поиск участника по имени/username, выбор из списка, переход из карточки и пересылка с открытым автором. Ручной ID остаётся дополнительным способом. История с фильтрами, журнал, импорт вайтлиста и CSV-выгрузки.
- Устойчивая очередь PostgreSQL: входящие updates и offset фиксируются вместе, задания имеют lease/heartbeat, модельные проверки могут выполняться параллельно. Отдельный worker обслуживает входящие события и кнопки.
- Результат Telegram хранится отдельно от намерения выполнить действие. Неоднозначные удаления и публикации не повторяются вслепую; старые и чужие баны не отменяются автоматически.
- Явная миграция старых данных с построчной сверкой. Исходные таблицы и Telegram ID сохраняются; неизвестное происхождение старых ограничений не выдумывается.
- Ежедневный согласованный бэкап PostgreSQL на VPS: последние семь успешных плановых копий и отдельная копия перед обновлением. Проверка восстановления, контроль свежести и безопасный запуск после восстановления.

## Окружение и запуск

Целевое окружение: Linux, Python 3.12, PostgreSQL 17 с актуальными исправлениями, Tesseract с `rus`, `ukr`, `eng`. Рабочий сервис запускается без root. Точные Python-зависимости закреплены в `requirements.txt` и `constraints.txt`.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Настройки окружения приведены в [.env.example](.env.example). Для обычного systemd-развёртывания боевые секреты размещаются вне checkout в `/etc/antiscam/bot.env`, с правами доступа только сервисному пользователю. Для Docker предусмотрены [контейнерные шаблоны](ops/container/README.md) с отдельными конфигурациями приложения, миграции, backup и health. Локальные политики и роли задаются в БД, а не наследуются из старого глобального `ADMIN_CHAT_IDS`.

**Не запускать новую точку входа поверх старой БД без миграции.** При запуске таблицы автоматически не создаются: проверяются версия Alembic, подтверждённый импорт и роли. Подготовка и порядок переноса описаны в [инструкции разработки](docs/DEVELOPMENT.md) и [инструкции эксплуатации](ops/README.md).

После успешной миграции и предрелизной проверки:

```sh
.venv/bin/python -m app.v2.preflight --telegram
.venv/bin/python -m app.main
```

`--telegram` выполняет чтение идентичности и прав, без тестовых публикаций и без запуска polling. Единственный работающий receiver с одним токеном обязателен. Предрелизная проверка дополнительно требует целевую Linux-систему и непривилегированного пользователя; её успешность на Windows не заявляется.

## Работа в Telegram

В личке — `/start`: владелец видит группы, заявки, запросы управляющих, состояние и финансы; администратор — свои заявки и подключение. В админской группе — `/as`: общая панель модерации с кнопками «Неразобранные», «История», «Участники», «Вайтлист», «Группы и настройки» и «Ещё». Для настроек выбирается рабочая группа; если она одна, лишний выбор пропускается. Подробные шаги — в [инструкции модератора](docs/MODERATOR_GUIDE.md).

| Режим | Поведение |
| --- | --- |
| 👁 Наблюдение | Проверки и карточки работают, новых автоматических наказаний нет; прогресс доверия учитывается |
| 🛡 Боевой | Выполняются разрешённые автоматические действия по правилам этой группы |
| ⏸ Пауза | Новые проверки и автоматические наказания остановлены; история и ограничения сохраняются |

Уже отправленное Telegram действие может завершиться после смены режима. Ручные действия модератора доступны независимо от автоматического режима. Повторное подключение начинается с наблюдения и сохраняет историю, списки и ограничения.

Вайтлист не снимает бан или мут. Разбан не выдаёт доверие и не обнуляет страйки. «Не скам» отменяет вклад конкретного случая, а разбан и размут выполняются отдельно. Блэклист — отдельный локальный запрет. Изменения записываются в журнал с автором.

## Код и проверки

| Путь | Назначение |
| --- | --- |
| `app/v2/` | Оперативный код V2 |
| `app/main.py` | Единственная точка входа V2 |
| `migrations/` | Alembic и зафиксированный DDL |
| `tests/` | Изоляция, конкурентность, восстановление заданий и интерфейс |
| `tools/` | Синтетическая нагрузка и офлайн-оценка модели |
| `ops/` | Systemd, резервное копирование, восстановление и независимое здоровье |
| `app/handlers/` | Сохранённый старый код для сравнения; новая точка входа его не запускает |

[Разработка и локальные тесты](docs/DEVELOPMENT.md) выполняются на отдельной `antiscam_test_*` базе localhost. Тестовые фикстуры очищают именно её. Тесты не используют боевой `.env`, Telegram/OpenAI-токены и не отправляют историю внешним API.

Для текущего развёртывания выбрана `gpt-6-luna`; модель задаётся явно через `OPENAI_MODEL`. Стоимость учитывает повышенный тариф записи кэша, при отсутствии подробностей расход оценивается консервативно. Короткие проверки API и синтетические примеры не заменяют независимую оценку качества на размеченном наборе. Последующие изменения модели требуют отдельной проверки доступности, параметров, качества и стоимости.

## Правила классификации

Глобальный промпт `antiscam-v2.8-bulk-advertising` относит к нарушениям обещания лёгкого заработка, расплывчатый набор без понятного работодателя и условий, объявления о покупке, продаже или обмене криптовалюты между участниками, сомнительные инвестиционные предложения, MLM и фишинг. К запрещённому набору также относятся обещания денег за неопределённую «небольшую помощь» с приглашением в личку или на другой профиль; конкретные законные поручения, возврат долга и обычные просьбы о помощи этим правилом не запрещаются. Также запрещена реклама и предложения продажи табака, сигарет, стиков, вейпов, жидкостей для них, алкоголя, лекарств и препаратов для похудения. Этот рекламный запрет действует во всех группах; обычные обсуждения, новости, вопросы и предупреждения с цитатами рекламы разрешены. Короткое «Куплю у вас USDT», продажа тезера и поиск участника для обмена на наличные также запрещены: цена, ссылка или доказательство обмана не обязательны. Причина должна объяснять запрещённое торговое объявление, а не утверждать доказанное мошенничество. Общие вопросы о покупке криптовалюты на бирже, комиссиях и безопасности, новости, прошлый опыт и критическое обсуждение цитат разрешены. Активный вайтлист сохраняет приоритет и исключает проверку. Глобально запрещена реклама услуг массового размещения по чатам/группам и нежелательных рассылок в личные сообщения, включая пакеты «реклама в 850+ чатах» и массовое распространение реферальных ссылок. Обычные объявления об услугах, дизайн баннеров, таргетинг, ведение соцсетей, согласование рекламы с администратором конкретной группы, рассылки добровольно подписавшимся клиентам и обсуждение спама разрешены. Упоминание рекламы, большой аудитории или реферальной ссылки само по себе не нарушает это правило.

`SCAM` — техническая метка нарушения политики, включая запрещённую рекламу, а не утверждение доказанного мошенничества. Уверенность модели не является измеренной вероятностью обмана. При оценке ниже локального порога (по умолчанию 80%) подозрительный случай направляется на рассмотрение без автоматического наказания. Доверие, исключения для администраторов, режим группы и остальные ограничения автоматических действий продолжают действовать.

Компактный промпт v2.9 сохраняет глобальные запреты и явно разрешает оплату обычного товара криптовалютой, обычные инвестиционные консультации без обещания обогащения и короткие вакансии с понятной работой. Дата выхода, наличие машины или переход в личку сами по себе не делают неопределённую подработку конкретной вакансией. Вопросы об использовании бирж, предупреждения и обсуждения защищены; предложение сделки между участниками остаётся запрещённым.

Вместимость входа ограничена `MAX_INPUT_CHARS=16000` для всего сериализованного текста системного и пользовательского сообщений. `MAX_INPUT_TOKENS=65536` — консервативная верхняя оценка по UTF-8-байтам с запасом на схему, а не фактическое число токенов. Она используется для проверки вместимости и предварительного резерва бюджета; после ответа учитывается usage провайдера. Явно заданный старый лимит `8000` продолжает действовать, поэтому при обновлении нужно проверить окружение. Полный исходник ответа допускает до 4096 символов; слишком большой общий запрос или недоступное содержимое требуют рассмотрения, текст не обрезается ради получения `OK`. Увеличение вместимости может увеличить расходы на сообщения, которые раньше вообще не доходили до модели.

Для оценки расхода используйте отдельный API-ключ тестового окружения и сравнивайте одинаковые сообщения по фактическому usage. Количество входных токенов, доля кэша и стоимость — разные показатели; тестовые запросы не должны смешиваться с боевой статистикой.

ТЗ, дизайн-атлас, боевой ранбук, дампы, скриншоты, локальные данные и секреты исключены из Git. Публичная документация содержит инструкции и результаты без конфигурации конкретного VPS. Локальные бэкапы не защищают от потери самого диска VPS; внешнее хранилище можно подключить отдельно, но оно не требуется для согласованного варианта.

При подключении групп автовайтлист не показывается и не настраивается. После подключения управление им доступно в настройках админской группы; действующие параметры и выданное доверие сохраняются.

Сообщения участника с действующим локальным доверием пропускаются до запросов статуса Telegram, OCR и модели: без новых карточек ошибок и автоматических наказаний. Отзыв/истечение доверия возобновляет проверки; в другой группе доверие не наследуется. Явный локальный блэклист сохраняет свой приоритет. Карточки самой выдачи/снятия доверия остаются доступны.

Пересылки проверяются как публикации отправителя. В ответах комментарий, полный доступный исходник, выбранная цитата, ссылки и источник передаются отдельно. Промпт учитывает продвижение сомнительных выплат отзывами «мне выплатили», но защищает предупреждения, вопросы, зарплату, социальные выплаты и конкретные законные банковские условия. Название канала не доказывает подлинность банка.

Если исходник отсутствует, обрезан или содержит непрочитанное медиа, сообщение направляется на рассмотрение без автоматических наказаний и прогресса автовайтлиста. Модель также может вернуть `REVIEW`, когда смысл доступной частичной цитаты недостаточен; это не `OK`. Для восстановления контекста используются только уже сохранённые неизменённые сообщения той же рабочей группы; внешние чаты и URL не загружаются. Карточка показывает комментарий, контекст и его неполноту. Лимит размера входа также приводит к рассмотрению, а не к молчаливому одобрению.
